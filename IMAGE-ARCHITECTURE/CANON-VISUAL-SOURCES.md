## Canon rule

A graphic contained in the approved source set is treated as an **official visual reference** unless a later explicit Canon Lock supersedes it.

The source image itself is never silently replaced by a newly generated image.

Generated images remain `PRODUCTION` until explicitly promoted to `CANON` by the project owner.

## Prompt derivation rule

For every approved visual asset, the production system may derive a reusable prompt specification from the visible source material.

The derived prompt must describe only observable or explicitly documented characteristics. Missing information must remain marked as unknown rather than invented.

Each derived prompt should remain linked to:

- source PDF
- source page(s)
- entity ID
- asset ID
- visual DNA
- prompt version
- Canon status

## Reuse rule

Approved visual sources may be reused across all five books and across character sheets, weapons, artefacts, biomes, fortresses, maps, scenes, and other production graphics, subject to the relevant Canon Locks.

## Versioning

If a later image is explicitly declared the new official appearance, the previous source remains in the archive/history and is not deleted. The new source receives a new version identifier.

## Important distinction

This registry records the **source authority** of the visuals. It does not claim that every visual element visible in a scene is independently canonized as a separate lore fact. Lore authority continues to come from the project Canon Locks and authoritative data records.
